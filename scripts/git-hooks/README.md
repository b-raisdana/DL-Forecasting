# git-hooks

Tracked source of `.git/hooks/pre-commit` (that dir isn't versioned by git - one-time setup per clone is `bash scripts/git-hooks/install.sh`, see [docs/infrastructure.md § environments](../../docs/infrastructure.md#environments)).

`pre-commit` doesn't invoke the `pre-commit` framework directly - it delegates to [precommit_wrapper.py](precommit_wrapper.py), which wraps `pre-commit run --hook-stage pre-commit` (config: `.pre-commit-config.yaml`) with:

- **failure snapshot**: staged index committed to a `snapshot/fix-<N>` branch, without touching the working tree, index, or HEAD (`git write-tree` / `commit-tree -p HEAD` / `branch -f`) - so a blocked commit never risks losing staged work. `N` is a counter in `.git/pc-seq` that only advances after a successful commit, so repeated failures within one fix-it-and-recommit session force-move the same branch (`-f`); the commit message still carries the attempt's human-readable timestamp even though the ref itself only ever points at the latest. The next session (after a success) gets a fresh, higher `N`.
- **logging**: every run (pass or fail) appends a JSON-line entry to `logs/pre-commit/pre-commit.log` (rolling summary - timestamp, branch, staged files, checks run, pass/fail result, and on failure the snapshot branch + `N`). On failure, `logs/pre-commit/fix-<N>/` (same `N` as the branch) accumulates a `<human-readable-timestamp>.log` (the pipeline's raw combined stdout/stderr, identical to what printed to the terminal) and `<human-readable-timestamp>.json` (that attempt's structured entry) per attempt - unlike the branch, this folder keeps every attempt in the session, not just the latest, for investigating a specific failed attempt in full later, e.g. when planning cleanup/optimization passes.
- **advisory lint warnings**: `Q`/`RUF`/`T10`/`T20`/`ERA` (quote conventions, Ruff-specific likely-bug checks, debugger statements, print() calls, commented-out code) are deliberately left out of `pyproject.toml`'s `[tool.ruff.lint] select` - no VS Code squiggle, no incremental-ratchet gate ([incremental-precommit/ratchet_check.py](incremental-precommit/ratchet_check.py) only ever sees whatever's selected). They're still surfaced here: a non-blocking stdout warning plus an `advisory_lint_warnings` (file, line, code, message) field in the log entry.

See [incremental-precommit/README.md](incremental-precommit/README.md) for the ratchet gate itself (mypy/ruff/xenon/loc, regression-only blocking).
